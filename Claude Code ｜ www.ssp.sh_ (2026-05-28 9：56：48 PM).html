# Broken Permissions with compound commands fixed

Claude basically broke the permission with compound commands:

When a Bash command contains compound operators (&&, |, ;, ||), the permission matcher evaluates the entire string as a single unit. This causes compound commands to require approval even when all individual components would be allowed by existing permission patterns. Feature: Parse compound Bash commands and match each component against permissions · Issue #16561 · anthropics/claude-code

This must be solved by Claude, but didn’t still. Compound commands are the default way of how Claude Code works, so if we need to manually approve each command, what’s the purpose of allowed global permissions in ~/.claude/settings.json?

Adding Bash (allow all) or --dangerously-skip-permissions is not an option for me.

The Oryband workaround with hooks worked like a charm for me, see the repo with the the minimal bash hook command: Page not found · GitHub · GitHub

WIthout that, CLaude forces you to approve each command individually. This one you can set the general approve list in claude.settings and if you say approve all on something else, it will keep it for the session (as it should).

This workflow let’s me still be in control, which I like.
